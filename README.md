# FocusMyTime

跨平台计时专注应用，支持 Windows、macOS、Linux、Android 和 Web。采用 Flutter 开发，多端体验一致。

## 核心功能

### 计时器系统
- **单核工作法**：自动计算到最近整点或半点，保证最少专注时长
- **番茄工作法**：专注 25min → 短休息 5min → 循环 → 长休息 15min（每 4 轮）
- 支持循环模式、自动开始下一轮
- **全方位通知系统**：专注或休息结束时触发铃声提醒、Windows 通知中心 Toast 以及应用内弹窗提醒

### 任务管理
- 多清单支持，自定义清单创建、编辑、删除
- **任务提醒事项**：类似 Microsoft To Do，支持设置指定日期的提醒，并支持 Windows 常驻闹钟模式。
- **全局时区设置**：支持跟随系统、北京、美国东部 3 种时区显示与时间输入，选项中直接展示 UTC 偏移。
- **版本更新检查**：启动后自动检查 GitHub Releases，也可在设置页底部手动检查最新版本。
- **跨清单拖拽**：长按任务拖拽到侧边栏其他清单，快速移动任务
- 重复任务：每天、每周、每月、每年循环
- 截止日期提醒，逾期任务红色高亮
- "我的一天"特殊视图

### 数据同步 (Cloud Sync)
- **多端同步协议**：基于 LWW (Last-Write-Wins) 的增量同步算法
- **软删除支持**：确保删除操作在所有设备间正确传播
- **自动触发**：任务变动及专注会话结束后自动同步至云端
- **反馈机制**：UI 实时显示同步状态及错误提示

### 备忘录（需求基线，实施中）

备忘录功能采用 Markdown 原文存储，支持普通备忘录和整篇加密的隐私备忘录。以下是已确认的产品规则，后续实现或测试发现偏差时必须同步更新本节。

- 支持文件夹（最多 10 层）、标签、置顶、归档、回收站和搜索；每篇备忘录属于一个文件夹，可有多个标签。
- Markdown 使用 GitHub Flavored Markdown 子集，支持表格、任务列表、删除线、代码块和代码高亮，默认不渲染原始 HTML。
- 支持粘贴/上传 PNG、JPEG、WebP、GIF；默认清理 EXIF，可选择保留；原图或压缩图二选一，并额外生成缩略图。
- 普通附件使用私有对象存储和短期签名地址；支持外链图片、可撤销公共直链和可选有效期/访问密码。外链由客户端直接加载，服务端不做代理缓存。
- 隐私保险库使用独立隐私密码和恢复密钥。密码不上传，云端只保存由密码或恢复密钥包装的主密钥、算法参数及密文。
- 隐私备忘录可按篇选择是否隐藏标题；隐藏标题时同时隐藏文件夹和标签关系。隐私正文、隐私附件和相关 AI 对话均只同步密文。
- 应用整体无操作默认 1 小时自动锁定，进入后台默认立即锁定；设置中可选择锁定延迟。解锁后可搜索隐私正文和查看本人全部附件。
- 当前版本之外，手动版本最多保留 20 个，自动恢复点最多 10 个，跨端冲突版本最多 10 个，三类互不挤占；恢复历史前先保存当前内容。回收站默认保留 30 天，历史版本引用的附件不能提前物理删除。
- 不设置用户固定容量配额。附件存储使用服务器对象存储所在磁盘的实际剩余空间，并始终预留 2GB；并发上传必须预留空间，低于保留线时暂停新上传。
- 私密附件支持加密分享页面；如用户明确确认，可另外发布明文副本并生成标准公共直链。私密对象本身永远保持密文。
- 支持跨所有端同步、离线上传队列、冲突版本保留、单个 Markdown/Typora 目录导入，以及 Markdown、图片 ZIP 和完整加密备份导出。
- AI 默认禁止读取隐私内容；用户可按篇授权，新会话首次使用时再次确认。第一阶段只发送选中文本或当前正文，不发送图片。

## 技术架构

| 组件 | 技术选型 |
|------|----------|
| 框架 | Flutter (Client) / Node.js (Server) |
| 语言 | Dart / TypeScript |
| 状态管理 | Riverpod |
| 数据库 | SQLite（原生 sqflite / WebAssembly SQLite） |
| 服务端 | Express + Better-SQLite3 |
| 主题 | Material 3（本地中文字体回退） |
| 通知 | windows_notification & local_notifications |
| 音频 | audioplayers |
| 同步服务 | LWW 增量同步协议 |

    - 服务端新增权威变更游标，客户端本地待上传水位与远端拉取游标分离，降低设备时间不准导致漏拉增量的风险。
    - 服务端仍保留客户端编辑时间用于 LWW 冲突判断，避免离线旧编辑仅因较晚上线而覆盖较新的已同步编辑。
    - 任务同步新增字段级更新时间元数据，服务端和客户端会按任务字段合并不同设备的离线修改；例如一台设备改标题、另一台设备改备注时，不再互相整条覆盖。
    - 数据库版本升级到 11，新增 `sync_field_versions` 表并在升级时回填现有任务字段版本，用于后续字段级冲突判断。
    - 修复旧同步服务端数据库升级时可能在新增 `server_updated_at` 列之前创建索引，导致服务启动失败的问题，并补齐 `sync_log` 表初始化。
    - 同步失败会显示更具体的阶段和错误原因，不再只提示“同步失败或未配置”，便于排查 Android 提醒、网络、登录和服务端问题。

## 服务端部署

本项目自带一个用于多端同步的 Node.js 后端服务，位于 `server/` 目录下。

### 1. 安装依赖

```bash
cd server
npm install
```

### 2. 配置环境变量

复制环境配置文件示例并进行配置：

```bash
cp .env.example .env
```

在 `.env` 文件中配置以下内容：
- `PORT`: 服务运行端口（默认 6677）
- `HOST`: 服务监听地址（生产环境默认 `127.0.0.1`，仅由本机反向代理访问）
- `JWT_SECRET`: 用于签发 Token 的密钥，请在生产环境务必修改为一个随机的长字符串。
- `CORS_ORIGINS`: 允许访问同步 API 的 Web 来源，多个来源使用逗号分隔。

### 3. 运行服务

开发环境运行：
```bash
npm run dev
```

生产环境部署（推荐使用 PM2）：
```bash
npm run build
pm2 start ecosystem.config.js
```
